# elifgezgin — Gezi

The site of Elif Gezgin, graphic designer, built as an interactive digital
artwork rather than a web page: one real-time 3D world with seven stops, and
scrolling walks the camera from one to the next. Next.js 16 (App Router),
React Three Fiber, drei, three.js, GSAP, Lenis. Turkish at `/`, English at
`/en`. The design system, the architecture and the honest limits are in
`docs/GEZI.md`.

- **01 RENK** — the entrance: chrome "ELİF", holographic "GEZGİN", liquid
  spheres, chrome ribbons, a particle field, fragments of the work floating
  past, a reflective floor. Dark void, electric blue, hot pink, cyan.
- **02 TİPOGRAFİ** — the typographic identity as a chrome word turning toward
  the hand, a ring of letters orbiting it. Cream, cobalt, orange.
- **03 MARKA** — the identity system inside one glass cube (real
  transmission), neon satellites. Deep purple, magenta, cyan.
- **04 AFİŞ** — the exhibition poster leaning toward the light; the poster
  series cut into cells that explode and gather again as the next sheet.
  Acid green and black.
- **05 DİJİTAL SANAT** — a generative piece projected onto a liquid sculpture,
  a magazine spread opening in space. White studio, chrome, coloured
  reflections.
- **06 ELİF** — the installation: the name in holographic glass at two depths,
  her statue on its plinth, the six disciplines drifting with the hand, a
  grid of ultraviolet light behind. Black, ultraviolet, lime.
- **07 İLETİŞİM** — four lines of type at four widths, a chrome knot turning
  slowly, the address only if there is one. Electric blue.

The light the visitor carries is the cursor: a point light in the scene and
a glowing sphere in the DOM, magnetic on links, labelled on projects. Every
project is a physical object you can click. Project pages are their own
experience (full-screen artwork, giant title, a small 3D stage, process,
details). No fabricated clients, awards or facts: the sample works are
generated by the repo and labelled "örnek proje".

Everything on the stage is procedural: letterforms are traced from the
site's own font and extruded, materials are shaders, the sample artwork is
rendered from SVG at build time. The only model is Elif's statue
(`public/models/`, meshopt-compressed GLB, two sizes). Fonts: Archivo
(variable width and weight, self-hosted subsets) and Instrument Serif.

## Run

```bash
npm install
npm run dev          # http://localhost:3000
npm run build && npm start
npm run lint
npm run typecheck
```

Fonts are subset with fonttools (`pyftsubset`); `public/fonts/archivo-tr.woff2`
is the Turkish letters and editorial punctuation of the variable Archivo,
cut from `assets/fonts/Archivo[wdth,wght].ttf`, so the first paint waits
for 11 KB of latin-ext instead of 86.

`prebuild`/`predev` run `scripts/samples.mjs` (renders the six sample works
only while `content/works` has no folders; `npm run samples` forces them) and
`scripts/prepare-content.mjs` (WebP derivatives at 2048/1600/800 px, blur
placeholders, a palette per work, a typed manifest in
`src/content/works.generated.ts`).

## Content

All content lives in `content/`: `site.ts` (name, title, description, tagline,
bio, disciplines, email, socials, availability, URL) and
`works/<slug>/meta.json` with the images next to it. `README_ELIF.md`
explains it in plain Turkish for Elif.

`meta.json`:

| field | meaning |
|---|---|
| `title`, `role`, `text` | `{ "tr": …, "en": … }` |
| `category` | `poster` · `typography` · `identity` · `digital` · `editorial` · `series` |
| `presentation` | how the work stands in 3D: `poster` · `chrome-type` · `glass-cube` · `projection` · `spread` · `particles` (default by category) |
| `stop` | the stop that shows it, 2–5 (default by category: typography 2, identity 3, poster/series 4, digital/editorial 5) |
| `year`, `tools`, `client`, `order`, `sample` | as named; `client` only when real, `sample: true` labels a sample |
| `colors` | two or three hex inks for the project page; otherwise taken from the cover |
| `process` | steps `{ "title": {…}, "text": {…} }` for the project page |
| `cover`, `gallery` | file names next to `meta.json` (jpg/png/webp) |

Each stop shows at most two works (one per presentation); every work is
linked from the contact stop's index and reachable from the project pages'
"next" link.

## Layout of the code

```
src/app                 (tr)/ and en/ root layouts, pages, isler/[slug] and en/work/[slug],
                        OG images (next/og), sitemap, robots, icon
src/components/3d       Experience (Canvas, DPR, tiers), World, CameraRig, Backdrop, Env,
                        CursorLight, ParticleField, Floor, Post, Tiering, WorkScene (project page),
                        text/ (glyph tracing → extrusion), materials, scenes/ (one per stop + Statue)
src/components/sections the HTML layer of each stop (semantic, server-rendered, works without WebGL)
src/components/ui       Navigation (and the phone menu), RouteIndex, CustomCursor, Loader,
                        SplitWord, CopyEmail
src/lib                 store, scroll (Lenis → p), stops (the route), tiers, i18n, meta, probe
src/styles              tokens, fonts, base, type, ui, stops, work
```

## URL switches

`?nogl` HTML only · `?gl=1` force the stage where the probe refused it (software renderers such as SwiftShader or llvmpipe, remote desktops, GPU tier 0 all get the HTML journey by default) ·
`?tier=ultra|high|mid|low` pin a quality tier · `?debug` exposes
`window.__r3f` (renderer, scene, camera) and `window.__stats()` for the
scripts.

```bash
node scripts/contrast.mjs [--gl] [--path /isler/<slug>]   # AA contrast against the rendered pixels
scripts/lighthouse.sh                                  # mobile + desktop, needs `next start`
```

All of these run the Playwright Chromium with SwiftShader (software WebGL):
frame times describe this machine, not a GPU.
